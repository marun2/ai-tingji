# 经营驾驶舱 · 设计说明

2026-11-25 重做。用户的反馈是“功能模糊，没明白要给用户提供什么体验”。这份文档把驾驶舱要解决什么问题、每块为什么在那里、以后怎么扩展和迭代写清楚。改驾驶舱之前先看这里。

## 一、定位：给谁用、解决什么问题

**用的人**：董事局（老板）和部门负责人（Connie、叶育彬、胡坤）。他们不会每天去翻会议记录。

**场景**：每周打开一次，用 3 分钟回答三个问题：
1. 这段时间各部门会上**说了什么**？（部门动态、热度变化）
2. 有哪些事**要我关注**？（需要关注）
3. 定下来了什么、提到了哪些**数**？（定下来的事、会上提到的数字）

**原则**：
- **先结论后细节**：最上面一行就是结论（几场会、几件事要关注、几项决定），往下才是明细。
- **每一条都能追到出处**：点一下就打开原会议；“追问”一键把问题带到提问页，由大模型翻会议回答。
- **诚实标注数据状态**：会议记录截至哪天、多久没导入、这期有几场会还没整理，都直接写出来，避免老板把“没数据”误读成“没问题”。
- **不出现人名**（用户要求）：只到部门、客户、平台、产品、话题这一层。

**旧版的问题**：最上面是“本周会议数 / 上周会议数 / 最近一场会 / 最近导入”这类数字，对经营判断没帮助；风险和决议只是按时间罗列，同一件事重复出现；没有时间范围和部门可选，也没有下一步动作。

## 二、模块（从上到下）

| 模块 | 回答的问题 | 怎么算 | 能做什么 |
|---|---|---|---|
| 顶部一行结论 | 这期总体怎样 | 会议数（和上一期比）、涉及几个部门、几件事要关注、几项决定 | — |
| 状态提示 | 数据靠不靠得住 | 会议记录截至日期；超过 7 天没导入就提醒；这期有几场会还没整理（抽取没完成）；待确认几场（只有管理员看得到） | 点“待确认”直接跳到知识库待确认 |
| **需要关注** | 有什么风险和问题 | 会上提到的风险。同一件事的不同说法合并（文字相似度），按“几场会提到 + 几个部门提到 + 上一期就有 + 最近 3 天还在提”排序。标“新出现”或“持续 · 自某天” | 看原会议、追问 |
| **热度变化** | 大家的注意力往哪走 | 客户、平台、产品、竞品、话题：这一期场次和之前 4 倍时长的平均水平比。明显变多的是“升温”，以前常提、这一期几乎不提的是“降温”。每行带近 8 周的小柱图 | 点一行就追问 |
| **定下来的事** | 形成了哪些决议 | 按部门分组，同一件事只留一条，标“几场会都提到” | 点开原会议 |
| **会上提到的数字** | 提到了哪些关键数 | 按指标归类（回款、销售额、铺市率、库存、费用、目标、产能……），同一个数重复说的合成一条。注明“来自会议发言，未经财务核实” | 点开原会议 |
| **部门动态** | 各部门在忙什么 | 每个部门：会议数（和上一期比）、风险几条、决议几条、聊得最多的 4 个词。上海食品的部门排前面，子公司在后 | 点一个部门，整个驾驶舱只看这个部门（下钻） |
| 会议节奏 | 开会频率的背景参考 | 近 12 周每周会议数 | — |

**时间范围**：本周 / 上周 / 近两周（默认）/ 本月 / 近 30 天。每种都自动配上“上一期”做对比，比如近两周对比之前两周、本月对比上个月。默认用近两周，是因为听记一般一周导一次，只看“本周”常常还没有数据。

**部门筛选**：右上角选部门，或者在“部门动态”里点。部门负责人只有研发市场销售一个范围，不显示这个选项。

**权限**：所有数字都按看的人的权限算，和知识库、提问用同一套规则。面试和私人内容的会不进驾驶舱（人事的其他会照常算）。

## 三、用户体验细节

- 进来先看到一行结论 + 状态提示，不用往下翻就知道这期大概怎样。
- 风险用颜色区分“新出现”（红）和“持续”（橙）。“持续”说明上一期就提过还没解决，最值得追问。
- 每条都有“看原会议”和“追问”。追问会带上一句完整的问题（原因是什么、谁在跟进、有没有定解决办法），老板不用自己组织语言。
- 数字统一标“未经核实”，避免直接当财务数据用。
- 手机上卡片自动排成一列，和电脑看到的内容一样。
- 某张卡片出错只显示“这块暂时出错了”，不影响其他卡片。

## 四、未来可扩展性

后端 `app/cockpit.py` 是“卡片注册表”：每张卡片一个函数，统一拿到时间段、对比段、权限范围、部门筛选这些上下文，返回自己的数据。`CARDS` 列表的顺序就是页面上的顺序。前端 `app.js` 的 `COCKPIT_CARDS` 里，每张卡片一个同名渲染函数，`CK_LAYOUT` 定宽度。

**加一张卡片 = 后端写一个函数 + 前端写一个渲染函数**，不用动其他地方。已经想到的扩展：

1. **接 KA 销售平台的真实数据**：在驾驶舱放“销售达成 / 备产预警”，和会上说的数字对照（会上说回款 85%，系统里实际多少）。需要中台开放应用之间互相查数据的口子，KA 平台已经有 `/__ask/` 查询口可以复用。
2. **目标跟踪**：从“定下来的事”里识别带日期的承诺（如“12 月 15 日前完成回款”），到期前后自动提醒“这件事后来怎样了”。
3. **AI 一段话简报**：用大模型把这期的关注、决议、热度写成 3～5 句话放在最上面（要花大模型用量，等余额稳定再开）。
4. **推送**：每周一把驾驶舱的结论行和“需要关注”推到飞书（需要中台加“应用发飞书消息”的接口，和“一周没导入提醒”是同一件事）。
5. **个人化**：老板可以把关心的客户、产品“钉住”，热度变化里优先显示。

## 五、持续迭代

1. **看使用数据**：每次点开会议、追问、展开原会议、点部门下钻、切时间，都记一次（表 `ui_event`，只记哪张卡片、什么动作、几次，**不记是谁**）。管理页「模型与检索 → 驾驶舱使用情况」能看近 30 天的统计。长期没人点的卡片就改掉或换掉。
2. **看追问记录**：从驾驶舱发起的追问都进提问记录，👍👎 能看出哪些问题答得不好，反过来改抽取或检索。
3. **抽取质量**：驾驶舱的内容全靠大模型抽取。分错类别的词在知识图谱里点一下就能改（`terms.py`）；风险、决议抽得不准，就改 `extract.py` 的提示词，然后在管理页“全部重抽”。
4. **合并规则可调**：同一件事的合并靠文字相似度，阈值在 `cockpit.py`（风险 0.42、决议 0.5）。合并过头或没合上，调这里。
5. **每次改版**：先在本文档更新“模块”表，再改代码；冒烟测试 `scripts/smoke.py` 里有驾驶舱的检查（六张卡片都能出数据、权限、时间段、点击统计）。
