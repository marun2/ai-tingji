# 部门协作 · 设计说明

2026-11-25 重做。用户反馈旧版“内容有点单一”：只有一张所有部门互相连线的圆环图，线密成一团，看不出结论；鼠标放到线上才有信息，手机和飞书里没法用；右边大块空白。

## 一、这一页要回答的问题

给董事局和负责人看，回答四个问题：
1. **哪些事是跨部门的？** 同一个客户、平台、产品或话题，好几个部门都在谈。
2. **这些事有没有拉通？** 有没有同时归到这几个部门的会（共同会议）。没有的标“没有共同会议”，提示可能需要对齐。
3. **哪两个部门联系最紧，在一起谈什么？**
4. **某个部门和谁协作最多？有哪些事只有它在谈？**

全部来自会议的文件夹归属和抽取出的关注点，**不调大模型**，点击只展开会议列表。

## 二、页面结构

| 位置 | 内容 | 交互 |
|---|---|---|
| 顶部一行 | 近 N 天：几个部门、几场跨部门会议（占比）、几个跨部门议题、几个没有共同会议；颜色图例 | 右上角切时间：30 天 / 90 天 / 半年 / 一年 |
| 左：部门关系图 | 业务板块在上方正中，上海食品职能部门在上半圈，子公司在下半圈。**实线**：一起开过会；**虚线**：只是关心相同的事；线越粗联系越紧。只画重要的线（每个部门最紧的 2 条 + 全局前 14 条） | 点部门：高亮它的线，右侧显示部门详情；点线：右侧显示这两个部门的详情；点空白：恢复总览 |
| 右：默认“联系最紧的部门” | 前 8 对部门：共同会议几场、共同关注几项、最主要的 4 个共同关注 | 点一行看这对部门的详情 |
| 右：部门对详情 | 共同会议数、共同关注数；一起关心的事，每项两边各几场（对比条）；共同会议列表 | 点会议看全文 |
| 右：部门详情 | 会议数、跨部门会议数和比例；和谁联系最多；最常谈到的事；只有这个部门在谈的事（七成以上提及都在这里） | 点合作部门跳到部门对详情 |
| 下：跨部门议题 | 至少 2 个部门、每个部门至少 2 场会都在谈的事。每行：名称和类别、各部门占比条、主要部门场次、有几场共同会议或“没有共同会议”、最近日期。“没有共同会议”的排得靠前 | 筛选：全部 / 没有共同会议 / 按类别；点一行展开每个部门最近的会，同时在关系图上高亮这些部门；默认显示 12 个，可以看更多 |

手机上不显示关系图（太挤），“联系最紧的部门”和“跨部门议题”已经能说明问题。

## 三、口径

- **共同会议**：同一场会同时归到两个及以上部门的文件夹。
- **共同关注**：两个部门的会里都出现过的客户、平台、产品、竞品、项目、区域、话题（抽取结果，套用了「关键词」修正）。
- **联系强度** = 共同会议数 × 3 + 共同关注加权。越少部门谈的事权重越高，避免“春节备货”这种人人都在谈的话题把所有部门连成一团。
- 按看的人的权限算。部门负责人只看得到研发市场销售，所以这一页对他们只会提示“只有一个部门”。面试和私人内容的会不算。
- “没有共同会议”只是说听记里没有同时归到这些部门的会，不等于真的没沟通（可能线下沟通过，或者会只归到了一个部门）。所以页面上写的是“可能需要对齐”，不下结论。

## 四、以后可以做

1. **时间对比**：两个部门的共同会议这期比上期多了还是少了（协作在变强还是变弱）。
2. **“没有共同会议”的提醒**：某个议题连续几周几个部门各谈各的，在驾驶舱的“需要关注”里提一句。
3. **人工标注**：管理员可以把某个议题标为“已线下对齐”，不再提示。
4. 点击次数记在 `ui_event`（卡片名 collab，动作 view / pair / dept / issue / filter / open），在管理页「驾驶舱使用情况」里能看到，用来判断哪些部分有人用。

代码：后端 `app/collab.py`（`build`），前端 `app.js` 的 `insCollab`，样式 `style.css` 末尾“部门协作 v2”。
