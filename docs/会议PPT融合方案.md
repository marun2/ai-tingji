# 会议材料（PDF）融合方案

2026-11-25 用户提出：上传会议 PPT 来补充会议内容。同日用户答复：**都是 PDF**；有的能关联到会议、有的不能；**原文件留在平台**，用户会定期删除过去的文件；PDF 里**图片和文字居多**。据此做了第一步，已上线（见文末“已实现”）。

## 为什么值得做
听记只有“会上怎么说”，PPT 是“会前准备了什么”：目标、预算、方案、数据表。两者合起来：
- 提问时能同时找到发言和材料，比如“盒马华东试点的目标是多少”，PPT 里往往写得比发言更准
- 驾驶舱的“会上提到的数字”可以区分“发言里说的”和“材料里写的”，后者更可信
- 周报月报能引用材料原文页码

## 整体思路：PPT 挂在会议下面，不单独成一个模块
用户不需要学新东西：打开一场会，多一个「材料」标签；提问、驾驶舱、报告自动把材料算进去。

### 1. 上传和匹配
- 「管理 → 导入」里多一个入口：上传 PPT（.pptx，也收 PDF，因为很多 PPT 会导出成 PDF 发），可以一次传多个或传 zip
- 系统按“文件名里的日期和标题 + PPT 首页标题 + 正文内容”和会议做匹配，给出建议，比如“《11月经营分析.pptx》→ 11-19 财务 KPI 指标与降本考核方案（把握 85%）”
- 管理员在一个核对页面里逐个点“确认 / 换一场 / 不挂会议”。把握很高的可以一键全部确认
- 也可以反过来：在某场会的页面里点“添加材料”直接上传，不用匹配
- 同一个文件重复上传自动跳过；同一份 PPT 的多个版本（初稿、终稿）只保留最新的，旧版标“已被替换”

### 2. 读取内容
- 逐页读出标题、正文、表格、图表里的数字、备注栏（讲稿），按页保存，**页码要保留**，方便引用“第 7 页”
- 纯图片页（截图、扫描件）先只记“这一页是图片”，不识别；要识别图片文字需要图像识别，会多花用量，见待定问题
- 原文件存在服务器的持久目录（和听记数据库分开），可以下载

### 3. 和现有功能怎么接
| 功能 | 怎么用上 PPT |
|---|---|
| 会议档案 | 会议详情多一个「材料」标签：每页一张卡片（标题 + 文字），可下载原文件；列表里有材料的会议显示一个小标记 |
| 搜索 | 能搜到 PPT 里的字，结果标“来自材料” |
| 提问 | PPT 按页切成检索段，和会议摘要、原文一起检索；回答的出处写成“《xx.pptx》第 7 页”，点开直接看那一页 |
| 抽取 | 每份 PPT 也抽决议、目标、数字、客户产品，标记来源是“材料” |
| 经营驾驶舱 | “会上提到的数字”区分“发言”和“材料”；同一指标两边都有时并排显示（如发言说回款 85%，材料写目标 90%） |
| 知识图谱 / 部门协作 | 材料里的客户、产品算进所挂会议 |
| 周报月报 | 写报告时把材料一起给大模型，出处可以引用材料页码 |
| 导出 Word | 会议导出时附“材料要点”（每页标题和要点），原 PPT 另附 |

### 4. 权限
- 材料跟着所挂的会议走：会议在哪个文件夹、谁能看，材料就一样
- 不挂会议的材料，先进「待确认」，只有董事局和管理员能看，由管理员归到文件夹
- 会议是敏感的（面试等），它的材料也敏感

### 5. 用量和存储
- 读文字不花大模型用量；每份 PPT 抽取一次约几千到一两万 tokens（按现在的价格不到 1 分钱）
- 向量化在服务器本地跑，不花钱，但每页都要算，几百份 PPT 第一次要跑一阵
- 原文件占磁盘：带图片的 PPT 一份可能几十 MB，几百份就是几 GB。需要确认中台服务器磁盘够不够，或者只留文字不留原件

## 分步做
1. **第一步**：上传 + 匹配核对 + 读文字 + 会议详情里看材料 + 搜索和提问能用到材料（最有用，先做）
2. **第二步**：抽取材料里的数字和决议，接进驾驶舱和周报月报
3. **第三步（看需要）**：每页缩略图（要在服务器装 LibreOffice 来渲染，环境会大几百 MB）、图片页文字识别

## 和“经营知识中枢”的关系
以前提过想把公司内部资料、文件也放进来。PPT 是第一种“非听记的材料”，这次把“材料”这个结构设计好（文件、逐页内容、挂到会议或文件夹、权限跟随），以后 PDF、Word、Excel 资料都能按同样方式接进来，不用再改一遍。到那时需要再和中台「资料」页定分工。

## 待定问题（开发前要问用户）
1. PPT 从哪来：会前汇报材料，还是会后整理的？文件名里一般有没有日期或会议名？大概有多少份、单个多大？
2. 一份 PPT 通常对应一场会，还是一份材料会在几场会上反复用？
3. 原文件要不要留在平台上供下载（占服务器磁盘），还是只要里面的文字？
4. 很多页是截图或图片表格的话，要不要识别图片里的文字？要识别就会多花一些用量
5. 除了 PPT，会议还有 PDF、Excel 这类材料吗？要不要一起考虑？
6. 材料只由你上传，还是也允许部门负责人给自己部门的会补材料？


## 已实现（2026-11-25，第一步）
- 「管理 → 会议材料」：一次上传多个 PDF（单个最大 200MB），同一文件重复上传跳过；列表分 全部 / 待核对 / 读取中 / 失败，显示总占用空间；每份可以换成建议的会、按标题搜会议改挂、不挂会议放进文件夹、标敏感、确认、删除（原文件和文字一起删）、失败的重新读取；可以勾选后批量确认
- 读取（`app/materials.py`，后台线程逐份处理）：PDFium 读文字层；文字少于 300 字或图片占页面四分之一以上的页，用 **RapidOCR 在服务器本地识别**（onnxruntime，模型随安装包，不联网、不花大模型用量），识别结果和文字层合并；**PDFium 不能多线程同时用，所有调用都加了锁**（否则整个服务会崩）
- 匹配：文件名 / 首页里的日期（前后 5 天内的会）+ 标题覆盖率 + 内容相似度，给出最多 4 个建议；把握够且明显领先就先挂上第一个（待核对），否则按内容猜一个文件夹（待核对）
- 权限：没确认的只有管理员和董事局能看；确认后挂在会议下的跟着会议权限走，没挂会议的按文件夹（部门负责人只看研发市场销售里、非敏感的）
- 查看：会议详情多一个「材料」标签（首页缩略图卡片）；会议档案左侧多一个「会议材料」入口；材料页面按页显示图片（按需渲染并缓存在 `materials/<id>.cache/`），每页可展开读出的文字，可下载原 PDF
- 搜索和提问：顶部搜索会列出“会议材料里也有”；提问时材料按页参与关键词 + 向量检索（文本段 `chunk.meeting_id = -材料编号`，`kind = material`），出处写“会议材料 第 n 页”，点开直接到那一页；回答里材料和发言数字不一致时分别列出
- 内存申请从 1536MB 提到 2048MB（OCR 模型）；Docker 里 opencv 换成 headless 版
